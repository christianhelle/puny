# Regenerating the provider clients

The clients under `src/providers` are generated by
[openapi2zig](https://github.com/christianhelle/openapi2zig) from the OpenAPI
specs in `src/providers/openapi`. Don't edit the generated files by hand. Change
the spec or the generator configuration, then regenerate.

| Spec | Output | Tags |
| --- | --- | --- |
| None (runtime only) | `src/providers/runtime.zig` | None |
| `openapi/openai.json` | `src/providers/openai/` | `Chat`, `Models`, `Responses` |
| `openapi/lmstudio.json` | `src/providers/lmstudio/` | `Models` |
| `openapi/anthropic.json` | `src/providers/anthropic/` | `Messages` |
| `openapi/google.json` | `src/providers/google/` | `models` |

Each spec directory gets a `client.zig` and a `contracts.zig`. All of them import
the shared `runtime.zig`.

There are two ways to regenerate. Use the build step unless you have a reason not
to, because it always uses the generator version the project pins.

## Option 1: the build step (recommended)

Run this from the repository root:

```sh
zig build regenerate-providers -Dregenerate-providers=true
```

The `-Dregenerate-providers=true` flag is required, and the step fails without it.
The flag keeps ordinary `zig build` and `zig build test` runs from fetching
openapi2zig, which is only needed here.

The step runs `generate_providers.zig`, which links openapi2zig as a library at
the version pinned in `build.zig.zon`, so you don't need the CLI installed. It does
the following:

1. Deletes the four generated output directories, so files a spec no longer
   produces don't linger.
2. Generates the shared runtime and each provider client.
3. Raises the SSE limits described in
   [step 3](#3-raise-the-sse-limits-in-the-runtime).
4. Applies the Google patches described in [step 4](#4-patch-the-google-client).

## Option 2: run openapi2zig manually

### 1. Use the pinned generator version

The CLI must be built from the same version as the dependency in `build.zig.zon`,
currently `v0.6.1`. Other commits can generate different code.

Don't rely on the version number to check this: a build made from a later commit
can still report `0.6.0`. To be sure, build the CLI from the tag:

```sh
git clone --depth 1 --branch v0.6.1 https://github.com/christianhelle/openapi2zig
cd openapi2zig
zig build
```

The binary is written to `zig-out/bin`. Make sure it comes first on your `PATH`, or
call it by its full path in the commands below.

### 2. Delete the old output and generate

Run these from the repository root. Delete the output directories first.

Bash:

```sh
rm -rf src/providers/openai src/providers/lmstudio src/providers/anthropic src/providers/google
```

PowerShell:

```powershell
Remove-Item -Recurse -Force src/providers/openai, src/providers/lmstudio, src/providers/anthropic, src/providers/google
```

Then generate the runtime and the clients. These commands work in both shells:

```sh
openapi2zig generate --runtime-only -o src/providers/runtime.zig
openapi2zig generate -i src/providers/openapi/openai.json -o src/providers/openai/ --multiple-files --file-name models=contracts.zig --runtime-module ../runtime.zig --tag Chat --tag Models --tag Responses
openapi2zig generate -i src/providers/openapi/lmstudio.json -o src/providers/lmstudio --multiple-files --file-name models=contracts.zig --runtime-module ../runtime.zig --tag Models
openapi2zig generate -i src/providers/openapi/anthropic.json -o src/providers/anthropic/ --multiple-files --file-name models=contracts.zig --runtime-module ../runtime.zig --tag Messages
openapi2zig generate -i src/providers/openapi/google.json -o src/providers/google/ --multiple-files --file-name models=contracts.zig --runtime-module ../runtime.zig --tag models
```

### 3. Raise the SSE limits in the runtime

The build step does this automatically, but the CLI doesn't. The generator caps an
SSE line at 256 KiB and an event at 1 MiB, which is too small for GitHub Copilot's
`response.completed` event. In `src/providers/runtime.zig`, set:

```zig
const max_sse_line_size = 16 * 1024 * 1024;
const max_sse_event_size = 32 * 1024 * 1024;
```

Keep both values equal to the ones in `src/providers/client.zig`.

### 4. Patch the Google client

The build step does this automatically, but the CLI doesn't. Without these patches
the Google client is wrong:

- **Request path:** `/v1beta/ss/` becomes `/v1beta/models/`.
- **Authentication:** `Authorization: Bearer <key>` becomes `x-goog-api-key: <key>`.
- **Recursive type:** `Schema.items` becomes `?*Schema`, because `?Schema` gives the
  type an infinite size.

Bash:

```sh
sed -i -e 's|/v1beta/ss/|/v1beta/models/|g' -e 's|"Bearer {s}"|"{s}"|g' -e 's|"Authorization"|"x-goog-api-key"|g' src/providers/google/client.zig
sed -i 's|^    items: ?Schema = null,|    items: ?*Schema = null,|' src/providers/google/contracts.zig
```

These use GNU `sed`. On macOS, use `sed -i ''` instead of `sed -i`.

PowerShell 7:

```powershell
$client = 'src/providers/google/client.zig'
(Get-Content $client -Raw).Replace('/v1beta/ss/', '/v1beta/models/').Replace('"Bearer {s}"', '"{s}"').Replace('"Authorization"', '"x-goog-api-key"') | Set-Content $client -NoNewline
$contracts = 'src/providers/google/contracts.zig'
(Get-Content $contracts -Raw).Replace('    items: ?Schema = null,', '    items: ?*Schema = null,') | Set-Content $contracts -NoNewline
```

## Check the result

```sh
git diff --stat
zig build test
```

If neither the specs nor the generator changed, the only difference in each client
and contracts file is the timestamp in its header. Any other change means the spec
changed, the generator version differs, or a patch was missed.

## Changing the configuration

If you change the tags, flags or patches, update both `generate_providers.zig` and
this file so the two options keep producing the same output. These CLI flags
correspond to the `generateFromSpec` options in `generate_providers.zig`:

| `generate_providers.zig` | CLI flag |
| --- | --- |
| `.input_path` | `-i` |
| `.output_path` | `-o` |
| `.multiple_files = true` | `--multiple-files` |
| `.file_names = .{ .models = "contracts.zig" }` | `--file-name models=contracts.zig` |
| `.runtime_module = "../runtime.zig"` | `--runtime-module ../runtime.zig` |
| `.tags = &.{ "A", "B" }` | `--tag A --tag B` |
| `.runtime_only = true` | `--runtime-only` |
